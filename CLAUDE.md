\# Amargon's Void Memory OS



\## Project rules



\- Analyze architecture before changing code.

\- Do not modify files unless explicitly requested.

\- Always inspect existing implementations before proposing changes.

\- Preserve tests and backwards compatibility.

\- Memory architecture is critical infrastructure.

\- SQLite schema changes require migration analysis.

\- Prefer small controlled changes over rewrites.



\## Workflow



Before coding:

1\. Locate entry point.

2\. Trace data flow.

3\. Identify dependencies.

4\. Explain risks.
