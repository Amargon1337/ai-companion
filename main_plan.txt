Отлично. Теперь это уже не просто план исправления багов, а **полная программа превращения Amargon's Void Memory OS в устойчивую долгоживущую Memory Platform**.

Я бы зафиксировал именно этот вариант как финальный roadmap. Я ещё немного поправлю детали Gemini, чтобы он был максимально практичным для твоего проекта.

Главное решение: **не Alembic/SQLAlchemy**.

Для этого проекта я бы оставил чистый SQLite + собственный migration engine.

Почему:

* у тебя уже есть собственный слой `MemoryDatabase`;
* SQLite используется напрямую;
* переход на ORM сейчас создаст огромный лишний слой;
* Alembic хорош для веб-приложений с SQLAlchemy, но здесь он будет бороться с твоей архитектурой.

Твой стек:

```
SQLite
+
собственный migration runner
+
versioned SQL/Python migrations
```

идеально подходит.
