Ревью кода проекта "AI Companion" (Amargon1337/ai-companion)
Дата: 2026-06-30

================================================================================
ОБЩИЙ ОБЗОР ПРОЕКТА
================================================================================
Проект представляет собой Telegram-бота на базе aiogram и google-genai, выполняющего функции персонального AI-компаньона. Архитектура проекта содержит интересные когнитивные слои: долгосрочную память (episodic, semantic, permanent), векторный поиск с кэшированием эмбеддингов, фоновый планировщик задач (рефлексия, обновление профиля), моделирование целей, предсказаний и причинно-следственных связей, а также поведенческий слой политик (Policy Layer) и систему самокритики (Self-Critique).

================================================================================
ПЛЮСЫ ПРОЕКТА (PROS)
================================================================================
1. Проработанная архитектура памяти:
   - Разделение памяти на сообщения (эпизодическая), факты (семантическая) и постоянные заметки (permanent).
   - Автоматическое сжатие истории диалога (консолидация в саммери через compress_and_reset) при превышении лимита сообщений.
   - RetrievalBudgetManager эффективно управляет лимитом токенов (символов) при генерации контекста для промпта.

2. Отказоустойчивость и асинхронность:
   - Синхронные вызовы API Gemini вынесены в отдельные потоки через asyncio.to_thread, предотвращая блокировку основного цикла событий (event loop).
   - Реализован паттерн Circuit Breaker в фоновом планировщике задач (background_scheduler.py). Это предотвращает спам логами при многократных сбоях сетевых запросов.
   - Использование asyncio.Semaphore ограничивает число параллельных фоновых задач (защита от перегрузки памяти OOM).

3. Безопасность записи данных:
   - Метод атомарной записи файлов в LegacyStorage (запись во временный файл с последующим переименованием/заменой) гарантирует отсутствие повреждений JSON-файлов при внезапном сбое процесса или выключении питания.

4. Локальный векторный поиск:
   - Использование локальной БД SQLite для хранения и cosine-similarity поиска по эмбеддингам текстов (VectorIndex) с резервным текстовым поиском по ключевым словам.

5. Богатый функционал интеграции с медиа:
   - Поддержка распознавания голоса, обработки PDF/DOCX документов, парсинга картинок/стикеров и скачивания TikTok (через yt-dlp) с мультимодальным анализом видео.


================================================================================
МИНУСЫ И КРИТИЧЕСКИЕ БАГИ (CONS & BUGS)
================================================================================
1. Критическая ошибка в critique_manager.py (Сбой самокритики):
   В функции run_self_critique() вызывается метод user_model.critique_response(). Однако у класса UserModel (из user_model.py) нет такого метода! Метод critique_response() определен в классе SelfModel (в self_model.py). Из-за этого при обработке каждого сообщения генерируется AttributeError, который гасится в try-except, и система самокритики всегда молча возвращает дефолтный пустой результат. Самокритика бота полностью не работает.

2. Разрушение форматирования в policy_layer.py (enforce_constraints):
   Метод enforce_constraints() разбивает текст ответа по переносам строк, а затем по точкам для фильтрации вопросов. При сборке обратно через ". " весь текст сливается в одну строку. Это полностью уничтожает форматирование markdown (списки, таблицы, блоки кода python превращаются в нечитаемую кашу в одну строку). Также парсер некорректно работает с вопросительными знаками (не разделяет предложения по "?").

3. Опечатка в companion/memory/store.py (reindex_all):
   В логе метода reindex_all() дважды передается counts["beliefs"] вместо counts["reflections"]:
   logger.info("Reindexed %d facts, %d beliefs, %d reflections, %d causal links", counts["facts"], counts["beliefs"], counts["beliefs"], counts["causal_links"])
   Из-за этого в логах пишется некорректное число рефлексий (вместо них дублируется число убеждений).

4. Уязвимость авторизации (Обход AuthMiddleware):
   AuthMiddleware в main.py проверяет только события types.Message. Глобальные обработчики CallbackQuery (inline_actions в handlers/chat.py) не проходят авторизацию. Сторонний пользователь может напрямую отправлять CallbackQuery-запросы к боту и получать приватные данные (профиль личности, саммери и т.д.).

5. Бесконечное накопление Predictions в predictions.jsonl:
   Функция maybe_capture_prediction() автоматически сохраняет вопросы пользователя о будущем в статусе "pending". Однако в проекте полностью отсутствует логика проверки и изменения статуса предсказаний на "verified" или "falsified". Список прогнозов будет расти и накапливаться бесконечно.

6. Захламление Goals сиюминутными желаниями:
   Heuristic regex в maybe_capture_goal() реагирует на слово "хочу" и при важности >= 6 автоматически добавляет цель в goals.jsonl. Фразы вроде "хочу спать" или "хочу пиццу" станут персистентными целями пользователя в базе данных.

7. Опасность Garbage Collection для proactive_ping_loop:
   В main.py фоновый таск запускается как asyncio.create_task(proactive_ping_loop(bot)), но ссылка на объект Task нигде не сохраняется. Сборщик мусора Python (GC) имеет право удалить этот таск во время работы, если на него нет сильных ссылок, что приведет к молчаливой остановке пинг-петли.

8. Высокий I/O overhead SQLite при импорте JSONL:
   В sqlite_db.py в методе _migrate_jsonl_if_empty() транзакция открывается и коммитится на КАЖДУЮ строчку JSONL:
   for row in read_jsonl(path): mapper(row) -> _insert_fact() -> opens _conn() -> commits.
   Это приводит к тысячам дисковых операций записи (fsync) при старте бота, если базы данных JSONL выросли. Необходимо использовать пакетную вставку (executemany) в одной транзакции.

9. Зависание потоков при таймауте LLM:
   В client.py метод run_llm использует asyncio.wait_for над asyncio.to_thread. При таймауте wait_for прерывает ожидание корутины, но запущенный поток в ThreadPoolExecutor невозможно убить из Python. Поток будет висеть в памяти до тех пор, пока сокетное соединение к Gemini не завершится естественным образом, что при серии таймаутов может исчерпать пул потоков.
