# AUDIT FIX PLAN

## Исправления (в порядке применения)

---

### FIX-1: Duplicate goals via NL intents (HIGH)

**Файл:** `services/reasoning_service.py`
**Функция:** `add_goal_from_text()`
**Баг:** NL-запрос "моя цель — ..." создаёт новый Goal без проверки дубликата. `maybe_capture_goal()` проверяет, но `add_goal_from_text()` — нет.
**Патч:** Добавить проверку существующих active goals перед созданием.
**Побочка:** Пользователь получит сообщение вместо создания дубля. Не критично.

---

### FIX-2: Prediction из всего текста сообщения (HIGH)

**Файл:** `reasoning.py`
**Функция:** `maybe_capture_prediction()`
**Баг:** Весь текст сообщения становится hypothesis prediction. Каждое уникальное сообщение → новый prediction. Нет лимита.
**Патч:** Ограничить `hypothesis` до 80 символов, убрать общие префиксы.
**Побочка:** Меньше текста в прогнозах, но меньше дублей.

---

### FIX-3: NL intent — "контекст" false positive (HIGH)

**Файл:** `intents.py`
**Баг:** `r"контекст"` без якоря — любое сообщение с этим словом уходит в `show_context()`.
**Патч:** Заменить на `r"^(покажи|дай|верни) контекст$"`, `r"^что было недавно$"`.
**Побочка:** Пользователям придётся писать точно "покажи контекст". Можно добавить ещё синонимы.

---

### FIX-4: NL intent — "я хочу " захватывает всё (HIGH)

**Файл:** `intents.py`
**Баг:** Любое "я хочу ..." → создание цели.
**Патч:** Заменить `r"я хочу "` на `r"^я хочу (достичь|добиться|научиться|стать|сделать|купить|получить|создать|перестать|начать)"`.
**Побочка:** Некоторые формулировки целей перестанут распознаваться. Можно расширять список глаголов.

---

### FIX-5: NL intent — "цель[\s—:-]" false positive (HIGH)

**Файл:** `intents.py`
**Баг:** "Цель данной функции — ..." создаёт Goal.
**Патч:** Убрать `r"цель[\s—:-]"`, оставить только `r"^моя цель"`.
**Побочка:** Потеряется формулировка "Цель: ..." (без "моя"). LOW risk.

---

### FIX-6: "отметь .*готов" — плохой паттерн (MEDIUM)

**Файл:** `intents.py`
**Баг:** `.*` захватывает любой текст, `_extract_index()` возвращает 0 → "Нет такого номера".
**Патч:** Изменить на `r"^отметь (\d+) (готовой|выполненной|сделанной)"` и использовать номер из группы.
**Побочка:** Меньше вариаций формулировок. LOW.

---

### FIX-7: "что ты помнишь" без контекста (MEDIUM)

**Файл:** `intents.py`
**Баг:** "Что ты помнишь о рекурсии?" уходит в `show_facts()`.
**Патч:** Добавить `$` (конец строки) ко всем паттернам facts-query.
**Побочка:** "Что ты помнишь обо мне?" тоже не сработает. Нужен компромисс: только если строка заканчивается после глагола.

---

### FIX-8: Cascading confidence в self-critique (MEDIUM)

**Файл:** `self_model.py`
**Функция:** `critique_response()`
**Баг:** Три checks перемножают confidence: 1.0 * 0.8 * 0.7 * 0.35 = 0.196.
**Патч:** Использовать `max reduction` вместо multiplication.
**Побочка:** Confidence будет выше → меньше grounding retries. Это и есть цель. MEDIUM — меньше false positives.

---

### FIX-9: "какой/какая" factual trigger слишком широкий (MEDIUM)

**Файл:** `bot_core.py`
**Функция:** `_should_retry_with_grounding()`
**Баг:** "какой" и "какая" встречаются почти в каждом русском предложении.
**Патч:** Только если слово стоит в начале предложения (вопросительное слово).
**Побочка:** Пропустит некоторые factual запросы с "какой" в середине. MEDIUM.

---

### FIX-10: auto_reasoning_context — sync I/O в async (CRITICAL)

**Файл:** `bot_core.py` / `reasoning.py`
**Функция:** `build_context()` / `auto_reasoning_context()`
**Баг:** `auto_reasoning_context()` читает 3 JSONL файла синхронно, блокируя event loop.
**Патч:** Обернуть вызов в `asyncio.to_thread()` в `build_context()`.
**Побочка:** Легкий overhead на создание потока (~50μs). Ниже latency для event loop.

---

### FIX-11: JSONL rotation не вызывается (CRITICAL)

**Файл:** `memory/store.py`, `reasoning.py`, `self_model.py`, `user_model.py`, `storage/legacy.py`
**Баг:** `rotate_jsonl()` существует, но не вызывается нигде. Все JSONL растут бесконечно.
**Патч:** Добавить вызов `rotate_jsonl()` после каждого `append_jsonl()` в каждом файле. Параметры: 50MB / 500k lines.
**Побочка:** Ротация — ещё один sync I/O. Но она триггерится только при превышении лимита (>50MB), не на каждую запись. LOW.

---

### FIX-12: World_model пишется слишком часто (LOW)

**Файл:** `reasoning.py`
**Функция:** `update_world_model_from_message()`, `_save_world_model()`
**Баг:** `_save_world_model()` вызывается на каждое qualifying сообщение.
**Патч:** Throttle — не чаще 1 раза в 10 секунд.
**Побочка:** При burst сообщений некоторые context updates пропустятся. LOW.
