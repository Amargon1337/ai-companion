# AI Companion — Техническая документация проекта

## 1. Общее описание

**AI Companion** — это персональный Telegram-бот для одного пользователя (Ivan).  
Бот реализует глубоко персонализированного ИИ-компаньона с долговременной памятью, эмоциональной моделью, причинно-следственным мышлением и самокритикой.  
Общается на русском языке с использованием нецензурной лексики в образе нигилистического ИИ «Амаргон».

### Стек технологий

| Компонент | Технология | Назначение |
|---|---|---|
| Язык | Python 3.11+ (аннотации из `__future__`) | — |
| Telegram API | `aiogram` 3.x | Приём и отправка сообщений, polling |
| LLM | `google-genai` (`google-generativeai`) | Gemini API (чат, поиск, эмбеддинги) |
| Чат-модель | `gemini-3.1-flash-lite` (через `MODEL_NAME`) | Все диалоговые ответы |
| Поисковая модель | `gemini-2.5-flash` (через `SEARCH_MODEL`) | Google Search grounding |
| Эмбеддинги | `text-embedding-004` (768 dim) | Векторный поиск фактов (RAG) |
| Аудио | `pydub` + `SpeechRecognition` | Распознавание голосовых сообщений |
| Видео | `yt-dlp` | Скачивание TikTok-видео |
| Документы | `pypdf`, `python-docx` | Извлечение текста из PDF и DOCX |
| База данных | SQLite (встроенный) | Основное структурированное хранилище |
| Файловое хранилище | JSONL (append-only) | Зеркало/WAL для SQLite |
| Конфигурация | `python-dotenv` | Парсинг `api.env` |
| Линтинг | Ruff + mypy | `pyproject.toml` |
| Тестирование | pytest | 5 тестовых файлов, моки LLM |
| Pre-commit | ruff, ruff-format, mypy | `.pre-commit-config.yaml` |

## 3. Архитектура и логика

### 3.1. Вход в приложение

`bot.py` → `companion.main.run()`:
1. Парсинг `api.env` (токен Telegram, Google API key, Admin ID).
2. Инициализация `aiogram Bot` и `Dispatcher`.
3. Установка `AuthMiddleware` — пропускает только админа (остальным — мат).
4. Регистрация хендлеров из `handlers/`.
5. Ротация JSONL-файлов (по 50К строк или 50МБ).
6. Переиндексация эмбеддингов из SQLite.
7. Запуск polling.

### 3.2. Обработка входящего сообщения

```
User → Telegram → AuthMiddleware → chat.py:text_handler
                                         │
                                    ┌─────┴──────┐
                                    │             │
                              intent?      process_llm_request()
                              (reset,       (основной pipeline)
                               show facts,
                               diary, etc.)
```

### 3.3. Основной pipeline (`bot_core.py:process_llm_request()`)

```
build_context()
  ├── check_rate_limit()          # 10 сообщений/мин
  ├── score_message_importance()  # эвристика 1–10
  ├── infer_mood_lite()           # keyword-based настроение
  ├── memory_store.log_message()  # SQLite + JSONL
  ├── reasoning.auto_reasoning_context()  # цели, причинность, предсказания
  ├── auto_add_event_from_message()       # если важно
  ├── classify_intent() → grounding?      # world/mixed → Google Search
  ├── policy_layer.detect_user_state()    # тревога/депрессия/любопытство
  └── _load_retrieval_context()           # факты, рефлексии, сводки

_generate_and_send_response()
  ├── retrieval_mgr.select()              # ранжированный контекст в бюджете
  ├── policy_layer.format_prompt_with_policy()  # правила ответа
  ├── llm.run_llm(chat.send_message)      # Gemini API
  ├── policy_layer.enforce_constraints()  # пост-обработка
  ├── run_self_critique() + apply_critique_to_text()
  ├── should_retry_with_grounding()? → grounding_answer_only()
  ├── send_long_message()                 # чанкованный ответ
  └── background_user_model_reflection()  # фоновая рефлексия
```

### 3.4. Сжатие памяти (каждые 50 сообщений)

```
run_compress_pipeline()
  ├── LLM: сводка разговора
  ├── LLM: извлечение фактов → add_fact()
  ├── LLM: консолидация (связи между фактами)
  ├── LLM: генерация рефлексий (каждые 4 цикла)
  ├── LLM: снэпшот личности
  ├── apply_importance_decay()            # экспоненциальное затухание
  └── update_master_summary()             # пожизненный контекст
```

### 3.5. Движение данных между модулями

```

     │       │
     │       ├── llm/pipeline.py (сжатие)

     │       └── llm/prompts.py (промпты)
     │
     ├──► memory/retrieval.py (выборка фактов)
     │       │
     │       ├── memory/importance.py (ранжирование)
     │       └── memory/vector_index.py (эмбеддинги)
     │
     ├──► reasoning.py (цели, предикции)
```

`RuntimeState` — dataclass, передаваемый через pipeline.  
Глобальные синглтоны: `memory_store`, `retrieval_mgr`, `user_chats`, `user_message_counts`.

## 4. Специфика Google API

### 4.1. Gemini Chat API (основной)

- **Модель**: `gemini-3.1-flash-lite` (конфигурируется через `MODEL_NAME`).
- **Клиент**: `genai.Client(api_key=GOOGLE_API_KEY)` — единый глобальный экземпляр.
- **Безопасность**: Все 4 категории (`HARASSMENT`, `HATE_SPEECH`, `SEXUAL`, `DANGEROUS`) — `BLOCK_NONE` (настраивается через env).
- **Параметры**: `max_output_tokens=8192`, `temperature=0.7` (чат) / `0.4` (поиск).
- **System instruction**: Полный русский промпт личности + динамически подгружаемый контекст (факты, рефлексии, сводки, цели, причинные связи, world model).

### 4.2. Google Search Grounding

- **Модель**: `gemini-2.5-flash` (через `SEARCH_MODEL`).
- **Активация**:
  1. `classify_intent()` определяет тип запроса: `world` (новости/погода/цены) или `mixed`.
  2. Если confidence >= 0.55 → `handle_grounding()` выполняет поиск.
  3. Если самокритика вернула низкую уверенность (< 0.55) → `grounding_answer_only()` повторяет запрос с grounding.
  4. Команда `/search` форсирует grounding.
- **Инструмент**: `google_types.Tool(google_search=google_types.GoogleSearch())`.
- **Источники**: `format_grounding_source()` извлекает URL из grounding metadata.

### 4.3. Embedding API

- **Модель**: `text-embedding-004`, 768 измерений.
- **Кэширование**: Эмбеддинги кешируются в таблице `embeddings` SQLite по SHA256(content hash).
- **Поиск**: Cosine similarity, порог > 0.3.
- **Отказоустойчивость**: При ошибке API возвращаются нулевые вектора (graceful degradation).

### 4.4. Обработка контекста и токенов

- **RetrievalBudgetManager** (`memory/retrieval.py`): выбирает факты, рефлексии и сводки в пределах `RETRIEVAL_CHAR_BUDGET` (4000 символов).
- **3-tier summary stack**:
  - Tier 1: последняя сводка (всегда включена).
  - Tier 2: 3 наиболее релевантные старые сводки (keyword overlap).
  - Tier 3: Master summary (пожизненный контекст, обновляется после каждого цикла сжатия).
- **Pinned facts guarantee**: факты с тегами `core_identity`, `anchor`, `pinned`, `permanent` или importance >= 9 всегда попадают в контекст.
- **Mood-aware boosting**: при тревожном/депрессивном настроении повышается вес «якорных» и позитивных фактов.

### 4.5. Retry-логика

`run_llm()` в `llm/client.py`:
- Асинхронная обёртка через `asyncio.to_thread()`.
- Таймаут: 120 секунд (конфигурируемый).
- Ретраи: 3 попытки с экспоненциальной задержкой (4 с, 8 с, 16 с).
- Обработка `TimeoutError` и общих исключений.

## 5. Особенности и фичи

### 5.1. Архитектурные особенности

- **Dual-write**: Все данные пишутся одновременно в SQLite и JSONL. JSONL — страховка на случай повреждения БД.
- **Атомарные записи**: `LegacyStorage._atomic_write()` — через tempfile + replace, очистка при ошибке.
- **Ротация JSONL**: `rotate_jsonl()` — разделение при 50К строк или 50МБ со сдвигом backup-файлов.
- **Circuit breaker**: Фоновые задачи отключаются на 10 минут после 5 последовательных ошибок.
- **Авто-восстановление сессий**: После рестарта бота последние 30 сообщений восстанавливаются из SQLite.

### 5.2. Кастомная эвристика

- **Mood Lite**: `mood_lite.py` — keyword-based анализ тревоги/гнева/грусти/энергии (не ML, помечено как технический долг).
- **Важность сообщений**: `score_message_importance()` — эвристика 1–10 по длине, знакам вопроса, словам-усилителям, именованным сущностям.
- **Затухание**: экспоненциальное с half-life 45 дней (state) / 120 дней (event) / бесконечно (permanent).
- **Сходство текста**: `text_sim.py` — Dice-коэффициент по 2- и 3-граммам, адаптировано для русского языка.

### 5.3. Личность и самосознание

- **Personality feedback loop protection**: `_merge_personality()` использует weighted average для интересов, дедупликацию для списков, merge для словарей — никогда полную замену.
- **SelfModel**: бот отслеживает свою уверенность по доменам (0.35 медицина, 0.95 архитектура), карту знаний о пользователе, статистику ошибок.
- **Политика ответа**: `PolicyLayer` детектирует состояние пользователя (ANXIOUS/DEPRESSED/CURIOUS/OVERWHELMED) и выбирает режим ответа (EXPLAIN/CONCISE/ANCHOR/EMPATHY).

### 5.4. Обработка ошибок (fallback chain)

| Сбой | Запасной вариант |
|---|---|
| LLM не ответил | 3 ретрая, потом сообщение об ошибке |
| Эмбеддинги недоступны | Нулевые вектора → keyword O(n) поиск |
| JSON не распарсен | Поиск в markdown-блоке → пустой результат |
| Сжатие памяти упало | return None, бот не падает |
| Master summary не обновился | Лог ошибки, старая сводка остаётся |
| Самокритика упала | Дефолт: confidence=1.0, без флагов |
| Кодировка документа | utf-8 → utf-8-sig → cp1251 → latin-1 |
| Голос не распознан | `UnknownValueError` → пользователю текст ошибки |
| Видео/файл не скачался | Пользователю сообщение об ошибке |

### 5.5. Логирование

- Rotating file handler: 10 MB, 3 backup, UTF-8, `bot.log`.
- Формат: `%(asctime)s [%(levelname)s] %(name)s: %(message)s`.
- Уровень: настраивается через `LOG_LEVEL` (default INFO).
- Логируются: сжатие, рефлексии, policy-решения, grounding, фоновые задачи, ротация JSONL, восстановление сессий, ошибки самосознания.

### 5.6. Известный технический долг (из кода и AUDIT_FIX_PLAN)

1. **Эвристический mood** — не ML, упоминание удалённого `mood_inference`.
2. **Линейный поиск фактов** — O(n) при отказе векторов.
3. **Потенциальные дубликаты целей** — `add_goal_from_text()` без проверки дубликатов (FIX-1).
4. **Чрезмерные предикции** — `maybe_capture_prediction()` анализирует всё сообщение (FIX-2).
5. **NL-интенты: ложные срабатывания** — regex «контекст», «я хочу » и др. (FIX-3–5).
6. **Дедупликация рефлексий не реализована** — отмечено в `self_model.py`.
7. **JSON-колонки в SQLite** — теги хранятся как JSON-строка, поиск через `LIKE`.
8. **Сохранение эмбеддингов каждые 10 документов** — лишний I/O.
9. **Одиночный пользователь** — `AuthMiddleware` блокирует всех, кроме админа.
10. **Тестовые env-переменные** — хардкод `test_key`, `test:token` в `conftest.py`.

### 5.7. Тестирование

- **pytest** с моками для LLM (`conftest.py`).
- 5 тестовых файлов покрывают: circuit breaker, самокритику, grounding, pipeline сжатия, retrieval budget.
- `fix_jsonl_encoding.py` — скрипт для восстановления UTF-8/CP1251 mojibake.
- `debug_db.py` — отладка схемы SQLite.
- `debug_pipeline.py` — тест pipeline с моками.
