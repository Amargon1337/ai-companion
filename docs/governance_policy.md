# Memory OS Governance Policy & Rules (Phase C2.0)

**Версия:** 1.0  
**Статус:** Зафиксировано перед началом разработки C2.1  
**Охват:** Правила жизненного цикла, права авторов (Actor Rules), защита ядра личности (Core Memory Protection), доверие и разрешение конфликтов.

---

## 1. Архитектурный принцип Governance

**Governance — это слой контроля (Validation & Policy Engine), а не второй MemoryStore.**
- `GovernancePolicyEngine` не заменяет хранилище и не дублирует API чтения/записи.
- Он отвечает на вопрос: *"Имеет ли автор (Actor) право выполнить операцию X над фактом Y в статусе S?"*
- Все изменения состояния обязаны проверяться через политику: `can_transition(old_status, new_status, actor, reason, fact_context)`.

---

## 2. Граф состояний жизненного цикла (Memory Lifecycle State Machine)

Статусы факта перестают быть произвольными строками. Разрешены только следующие состояния и направленные переходы между ними:

```
                  ┌──────────────────────────────────────────────┐
                  │                                              ▼
            ┌───────────┐      apply_decay()               ┌───────────┐
            │           │ ───────────────────────────────> │           │
 ─────────> │  ACTIVE   │                                  │  DORMANT  │
  (create)  │           │ <─────────────────────────────── │           │
            └───────────┘       revive_dormant()           └───────────┘
              │       │                                      │       │
              │       │ supersede()                          │       │ archive()
              │       ▼                                      │       ▼
              │   ┌────────────┐                             │   ┌────────────┐
              │   │ SUPERSEDED │                             │   │  ARCHIVED  │
              │   └────────────┘                             │   └────────────┘
              │                                              │         │
              │ quarantine()                                 │         │ restore()
              ▼                                              ▼         ▼
            ┌─────────────┐     verify()      ┌─────────────────────────┐
            │ QUARANTINED │ ────────────────> │         VERIFIED        │
            └─────────────┘                   │  (или возврат в ACTIVE) │
                   │                          └─────────────────────────┘
                   │ delete() [только ADMIN/SYSTEM]
                   ▼
            ┌─────────────┐
            │   DELETED   │
            └─────────────┘
```

### 2.1 Таблица валидных переходов

| Исходный статус (`old_status`) | Целевой статус (`new_status`) | Разрешённые авторы (`Actor`) | Описание / Условие |
| :--- | :--- | :--- | :--- |
| *(None / New)* | `ACTIVE` | `USER`, `LLM`, `SYSTEM`, `ADMIN` | Создание нового факта |
| `ACTIVE` | `DORMANT` | `SYSTEM`, `ADMIN` | Затухание важности (`importance decay`) при неиспользовании |
| `ACTIVE` | `QUARANTINED` | `SYSTEM`, `ADMIN`, `USER` | Обнаружение конфликта или сомнение в достоверности |
| `ACTIVE` | `SUPERSEDED` | `USER`, `SYSTEM`, `ADMIN` | Замещение фактом с высшим приоритетом/свежестью |
| `DORMANT` | `ACTIVE` | `USER`, `SYSTEM`, `ADMIN` | Восстановление активности при успешном поиске / обращении |
| `DORMANT` | `ARCHIVED` | `SYSTEM`, `ADMIN` | Долгосрочная архивация неиспользуемой памяти |
| `DORMANT` | `QUARANTINED` | `SYSTEM`, `ADMIN` | Обнаружение аномалии или конфликта |
| `ARCHIVED` | `RESTORED` (`ACTIVE`) | `USER`, `ADMIN`, `SYSTEM` | Явное извлечение или запрос на восстановление |
| `QUARANTINED` | `VERIFIED` (`ACTIVE`) | `USER`, `ADMIN` | Подтверждение пользователем или администратором |
| `QUARANTINED` | `DELETED` | `ADMIN`, `SYSTEM` | Окончательное удаление недостоверной или вредной информации |

## 3. Защита ядра личности (Core Memory Protection)

Память, определяющая идентичность и фундаментальные убеждения системы, защищена от автоматических изменений:

1. **Несгораемый слой (Immutable / Protected Identity):**
   - Факты с `identity_layer`, равным `CORE_VALUE`, `CORE_BELIEF` или `CORE_IDENTITY`:
     - **Не могут быть удалены** (`DELETED`) автоматическими процессами (`LLM`, `SYSTEM`).
     - **Не могут быть архивированы** (`ARCHIVED`) или переведены в `DORMANT` через затухание (`importance decay`).
     - **Не могут быть замещены** (`SUPERSEDED`) автоматическим выводом (`LLM_INFERENCE`).
2. **Исключение:** Изменить статус защищённого факта может только явная директива пользователя (`USER`) или администратора (`ADMIN`) с генерацией события `CORE_VALUE_PROTECTED` / `IDENTITY_LAYER_CHANGED`.

---

## 4. Правила доверия и разрешения конфликтов (Trust & Confidence Rules)

1. **Приоритет наблюдений над выводами (Observation vs Inference):**
   - Факт, полученный через прямое утверждение пользователя (`origin = USER_STATEMENT` или `source_type = user`), не может быть автоматически перезаписан или замещён фактом, созданным через логический вывод (`origin = LLM_INFERENCE`), даже если числительное значение `confidence` у LLM-вывода выше.
2. **Иерархия источников при арбитраже:**
   ```
   USER_STATEMENT > VERIFIED_OBSERVATION > SYSTEM_INFERENCE > LLM_EXTRACTION > LLM_INFERENCE
   ```
3. **Требование фиксации коллизии:**
   - При попытке добавления противоречащего факта в обход иерархии должно генерироваться событие `CONFLICT_DETECTED`. Автоматическая замена без разрешения конфликта (`CONFLICT_RESOLVED`) запрещена.

## 5. Права субъектов системы (Actor Rules)

| Субъект (`Actor`) | Создание (`ACTIVE`) | Затухание (`DORMANT`) | Архивация (`ARCHIVED`) | Карантин (`QUARANTINED`) | Удаление (`DELETED`) | Модификация `CORE_VALUE` |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **`USER` / `ADMIN`** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| **`SYSTEM` (Background jobs)** | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |
| **`LLM` (Extraction / Inference)** | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |

- **`LLM`:** Не имеет права напрямую архивировать, удалять или гасить факты. Модель может лишь предлагать новые факты или отношения (`supersedes`), которые проверяются через `GovernancePolicyEngine`.
- **`SYSTEM`:** Может переводить память в `DORMANT`, `ARCHIVED` или `QUARANTINED` по регламенту (decay/retention), но не может удалять или изменять `CORE_VALUE`.
