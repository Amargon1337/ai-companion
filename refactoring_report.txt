# Refactoring Report — LLM Analyzer Migration

## Что сделано

### Проблема
Эвристический анализ настроения (`mood_lite.py`) и регулярные выражения для интентов (`intents.py`, `llm/grounding.py`) были заменены на единый LLM-запрос через Gemini.

### Изменённые/созданные файлы

| Файл | Действие | Описание |
|---|---|---|
| `companion/llm/analyzer.py` | **Создан** | Единый LLM-анализатор: вызывает `oneshot()` с промптом и возвращает строгий JSON с полями `intent`, `confidence`, `user_mood`, `user_state`, `estimated_importance`, `command` |
| `companion/runtime_state.py` | **Изменён** | Добавлены поля: `user_state`, `intent`, `intent_confidence`, `command` |
| `companion/bot_core.py` | **Изменён** | — `build_context()`: вместо `score_message_importance()` + `infer_mood_lite()` + `classify_intent()` теперь один вызов `analyze_message()` через `asyncio.to_thread`<br> — `_get_policy_decision()`: использует `PolicyLayer.from_analyzer_state()` вместо `detect_user_state()`<br> — `_route_command()`: новый метод, маршрутизирует команды по полю `command` из LLM-анализа (вместо regex в `intents.py`)<br> — `process_llm_request()`: если `intent == "command"`, вызывает `_route_command()` и выходит, минуя генерацию ответа |
| `companion/memory/retrieval.py` | **Изменён** | — `mood_to_retrieval_boost()` перенесена из `mood_lite.py` внутрь `retrieval.py` (единственный потребитель)<br> — `select()` принимает опциональный параметр `mood` вместо вызова `infer_mood_lite()`<br> — удалён импорт `from companion.mood_lite import ...` |
| `companion/policy_layer.py` | **Изменён** | Добавлен статический метод `from_analyzer_state(state_str)` — конвертирует строку состояния из LLM-анализа в `UserState` enum |
| `companion/handlers/chat.py` | **Изменён** | Удалён импорт и вызов `try_handle_intent()`; маршрутизация команд теперь в `bot_core._route_command()` после LLM-анализа |
| `companion/intents.py` | **Переписан** | Заглушка с комментарием о замене на LLM-анализатор |
| `companion/mood_lite.py` | **Удалён** | Вся логика перенесена: `mood_to_retrieval_boost()` → `retrieval.py`; анализ настроения → `analyzer.py` |

### Детали реализации новой архитектуры

**До (heuristic):**
```
→ build_context()
    → score_message_importance()       # эвристика в importance.py
    → infer_mood_lite()                # keyword-анализ в mood_lite.py
    → classify_intent()                # regex в llm/grounding.py
    → detect_user_state()              # keyword-анализ в policy_layer.py
```

**После (LLM):**
```
→ build_context()
    → analyze_message()                 # единый LLM-запрос
        → intent, confidence
        → user_mood (anxiety/anger/sadness/energy)
        → user_state (ANXIOUS/DEPRESSED/CURIOUS/OVERWHELMED/NORMAL)
        → estimated_importance (1-10)
        → command (если intent == "command")
    → PolicyLayer.from_analyzer_state()  # конвертация строки в enum
```

**Промпт анализатора** (`llm/analyzer.py`):
- Запрашивает у Gemini структурированный JSON
- Валидирует все поля (intent, user_state проверяются по whitelist)
- Fallback при ошибке: безопасные значения по умолчанию (chat_casual, NORMAL, importance=5)
- Таймаут/ретраи через существующий `run_llm()` / `oneshot()`

### Совместимость

- `RuntimeState.mood_state` сохранил тип `dict | None` с ключами `anxiety/anger/sadness/energy` — полная обратная совместимость с `retrieval.py` и `user_model.py`
- `select()` принимает `mood` как опциональный параметр — все старые вызовы без него работают
- Файл `companion/llm/grounding.py` не удалён (классический `classify_intent()` остаётся для потенциального использования)
