ПЛАН РЕАЛИЗАЦИИ: CONTEXT-AWARE PROACTIVE LOOP (V1)

ЦЕЛЬ:
Создать управляемый, контекстно-зависимый цикл проактивности, где решение о пинге и выбор причины принимает детерминированный код, а LLM занимается только финальной формулировкой с учетом Policy Engine (Dynamic Tone).

---
АРХИТЕКТУРНЫЙ ПАЙПЛАЙН:

1. SCHEDULER (Инициатор)
- Запускается по Cron / фоновому таймеру.
- Передает управление Engagement Gate.

2. ENGAGEMENT GATE (Решение "писать или не писать")
- Защита от спама и выгорания пользователя.
- Факторы оценки (Engagement Score):
  - Часы молчания (с момента последнего ответа пользователя).
  - Активность за последние 7 дней.
  - Текущий `baseline_state` (депрессия требует больше заботы, нейтральность — меньше пингов).
  - Штраф за проигнорированные пинги (например, 3 неотвеченных пинга подряд = silent mode).
- Если Gate не пропущен -> отмена пинга.

3. REASON SELECTOR (Выбор причины из жесткого списка)
- LLM не участвует в выборе причины. Это предотвращает галлюцинации ("ты вчера говорил...").
- PING_REASONS Enum:
  1. `unfinished_goal`: Есть открытые задачи/цели.
  2. `unfinished_conversation`: Предыдущий диалог завершился вопросом или завис (`status = open`).
  3. `emotional_checkin`: Валидно только если `baseline_state` == `depressed` или `anxious`.
  4. `achievement_followup`: Недавнее достижение/закрытая цель.
  5. `long_silence`: Просто долгое отсутствие (fallback-вариант).

4. CONTEXT COLLECTOR (Сборщик данных под причину)
- `unfinished_goal` -> тащит открытые цели из Reasoning Graph или TODOs.
- `unfinished_conversation` -> тащит последние сообщения из MemoryStore (где status=open).
- `emotional_checkin` -> тащит последние триггеры/сигналы (signals) из UserModel.
- `achievement_followup` -> тащит недавно закрытые цели/заметки.

5. POLICY ENGINE (Слой из Dynamic Tone V6)
- Применяем `current_state` -> `STRATEGY` + `TONE`.

6. LLM FORMATTER
- Сборка итогового промпта: 
  Причина + Контекст Причины + Стратегия + Тон -> LLM -> Text.
- Жесткая инструкция для LLM: "Ты пишешь ПИНГ. Коротко, в соответствии с тоном, не выдумывай новые факты, используй только предоставленный контекст."

7. TELEGRAM SENDER
- Отправка сообщения.
- Запись пинга в БД (обновление счетчика неотвеченных пингов).

---
ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
Компаньон перестает быть генератором случайных сообщений. Проактивность становится осмысленной, предсказуемой для разработчика, но живой и эмпатичной для пользователя.
