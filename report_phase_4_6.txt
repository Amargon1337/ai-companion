AI COMPANION — Phase 4-6 Implementation Report
===============================================

Date: 2026-06-24

PHASE 4: Vector Memory (RAG) Infrastructure
--------------------------------------------
Created `companion/memory/vector_index.py` — embedding caching layer using
Gemini's text-embedding-004 API with SQLite storage:

  - `VectorIndex` class manages embedding storage in a dedicated `embeddings`
    table (content_hash PK, content, embedding BLOB, content_type, created_at)
  - `_embed_texts()` — batched embedding via Gemini API, falls back to zero
    vectors on failure/fake API keys (test-safe)
  - `cosine_similarity()` — pure-Python vector similarity
  - `search(query, top_k, content_type)` — vector search with score filtering
    (threshold 0.3), returns ranked results
  - `compute_and_cache()` / `compute_and_cache_batch()` — on-demand embedding
    with dedup by SHA256 content hash
  - `_float_list_to_blob()` / `_blob_to_float_list()` — efficient struct packing

Modified `companion/memory/store.py`:
  - `MemoryStore.__init__()` now initializes `self.vector = VectorIndex()`
  - `search_facts()` — tries vector search first, falls back to O(n) keyword
  - `add_fact()` — auto-indexes new facts into vector DB
  - `add_belief()` — auto-indexes new beliefs
  - `reindex_all()` — bulk reindexes facts, beliefs, reflections, causal links

Modified `companion/main.py`:
  - Calls `memory_store.reindex_all()` on startup after JSONL rotation

Fixed critical bug: Python default parameter values for `SQLITE_PATH` were
evaluated at module import time, causing test fixtures using `tmp_path` to
inadvertently use the production database. Changed both `MemoryDatabase` and
`VectorIndex` to read config at instantiation time.

PHASE 5: Session Persistence & Async Upgrade
---------------------------------------------
Modified `companion/storage/sqlite_db.py`:
  - Added `sessions` table (user_id PK, message_count, last_active, created_at)
  - Added `save_session()`, `load_sessions()`, `delete_session()`, `count_sessions()`

Modified `companion/bot_core.py`:
  - Added `_persist_session(uid)` helper
  - `_init_user_session()` persists session after creation
  - `compress_and_reset()` persists session after successful reset
  - `_restore_sessions()` loads saved sessions from DB into memory
  - `build_context()` calls `_restore_sessions()` on first invocation

Modified `companion/llm/client.py`:
  - Added native async Gemini client via `_get_aio_client()` (lazy init)
  - Added `aio_oneshot()`, `aio_search_with_grounding()`, `aio_upload_file()`,
    `aio_get_file()` — true async versions using `client.aio`
  - Existing sync wrappers (`async_oneshot`, etc.) kept for backward compat

PHASE 6: Test Suite Expansion
------------------------------

  tests/test_grounding_handler.py (5 tests):
    - factual WH-questions trigger retry
    - non-factual questions do not trigger retry
    - warning containing "source" triggers retry

    - empty query does not trigger retry

  tests/test_critique_manager.py (8 tests):
    - high confidence + no warnings returns text unchanged
    - high confidence + warnings adds prefix and suffix
    - low confidence adds "not sure" prefix
    - medium confidence adds "looks like" prefix
    - uncertain_language flag skips prefix
    - uncertain_language with warnings appends warning
    - empty text does not crash
    - low confidence + warnings adds both prefix and warning

  tests/test_background_scheduler.py (7 tests):
    - initial state allows execution
    - few failures still allows execution
    - max failures triggers cooldown
    - success resets failure count
    - after cooldown expires, execution resumes
    - different tasks have independent circuit breakers
    - exactly at max failures triggers circuit breaker
